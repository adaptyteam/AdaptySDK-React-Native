# AdaptyDevtoolsSpm

The same devtools UI as [`examples/AdaptyDevtools`](../AdaptyDevtools), but the iOS project is
integrated through React Native's **experimental Swift Package Manager support**
(`npx react-native spm`, RN 0.87+) instead of CocoaPods.

It exists to exercise the SwiftPM path of `react-native-adapty` — the repo's root
[`Package.swift`](../../Package.swift) — which CocoaPods never reads.

## iOS: no `pod install`

There is no CocoaPods integration here. `ios/Podfile` is kept **as a marker only**: the React
Native CLI resolves `project.ios.sourceDir` from the Podfile's location and autolinking fails
without it. Do not add pods to it and do not run `pod install` — that would break the SwiftPM
package graph.

The SwiftPM equivalent of `pod install` is:

```sh
yarn update-native-modules      # = cd ios && npx react-native spm
```

Run it after a fresh clone, after every `yarn install`, and after every `yarn update-sdk-full`.

> `yarn install` also **replaces the locally built SDK** with the published `latest` from npm
> (`react-native-adapty` is declared as `"latest"`, same as in `examples/AdaptyDevtools`). After any
> install, re-run `yarn update-sdk-full && yarn update-native-modules` — otherwise you are testing
> the released SDK, and `yarn tsc` will fail on APIs that only exist in this working copy.

> **Why it is not optional.** The Xcode project carries a `Sync SPM Autolinking` build phase that
> regenerates the autolinking manifest, but it runs *inside* the build — after Xcode has already
> resolved the package graph. A build started right after the SDK was reinstalled therefore
> **succeeds while silently omitting the dependency**. Always run the command above first.

## Local SDK build

```sh
yarn update-sdk-full            # build react-native-adapty from this repo and install it here
yarn update-native-modules      # re-run SwiftPM autolinking (see above)
```

## Run

```sh
yarn credentials                # writes .adapty-credentials.json (gitignored)
yarn start                      # Metro
yarn ios                        # or: yarn android
```

`yarn credentials` also rewrites `PRODUCT_BUNDLE_IDENTIFIER` in `project.pbxproj`. That change is
local only — the committed project keeps the template identifier, so revert the pbxproj before
committing.

## Patched dependencies

`react-native-screens` and `react-native-safe-area-context` ship no `Package.swift`. Theirs are
generated by `npx react-native spm scaffold` and persisted with
[`patch-package`](./patches) — that is why `postinstall` runs `patch-package` and why both
libraries are pinned to exact versions (a patch file is tied to the version in its name).

`react-native-screens` needed one manual edit on top of the scaffold: its
`ios/tabs/host/RNSTabsHostComponentView.mm` includes `<rnscreens/RNSTabsHostComponentDescriptor.h>`
while that header lives in `common/cpp/react/renderer/components/rnscreens/`, so
`common/cpp/react/renderer/components` was added to the target's header search paths.

**When React Native is upgraded, the patches must be regenerated** — a scaffolded manifest is
stamped with a cache slot (e.g. `0.87.1/dual-flavor`) and relative paths computed at scaffold time:

```sh
rm node_modules/react-native-screens/Package.swift \
   node_modules/react-native-safe-area-context/Package.swift
npx react-native spm scaffold
npx patch-package react-native-screens
npx patch-package react-native-safe-area-context
```

## Verify the build

```sh
# Debug (simulator)
xcodebuild -project ios/AdaptyDevtoolsSpm.xcodeproj -scheme AdaptyDevtoolsSpm \
  -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath ios/build/DD -skipPackagePluginValidation CODE_SIGNING_ALLOWED=NO build

# Release (device, unsigned) — link errors show up here and not in Debug
xcodebuild -project ios/AdaptyDevtoolsSpm.xcodeproj -scheme AdaptyDevtoolsSpm \
  -configuration Release -sdk iphoneos -destination 'generic/platform=iOS' \
  -derivedDataPath ios/build/DD-release -skipPackagePluginValidation \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build
```

A green build alone does not prove Adapty was linked. Check the symbol and the resolved pin:

```sh
nm ios/build/DD-release/Build/Products/Release-iphoneos/AdaptyDevtoolsSpm.app/AdaptyDevtoolsSpm \
  | grep -c RNAdapty
grep -A4 -i adaptysdk-ios \
  ios/AdaptyDevtoolsSpm.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved
```

The resolved version comes from the SDK's `Package.swift`, not from
`react-native-adapty-sdk.podspec`.

## Android

Unchanged from the standard template — SwiftPM affects iOS only. Android CI coverage lives with
`examples/AdaptyDevtools`; this app is not built for Android in CI.

## No unit tests

The template's render smoke test was removed: it cannot run without credentials and native modules,
and this example's purpose is native-path verification (build + runtime), not JS unit testing.
